# Полная спецификация и архитектура ИИ боевых ботов (Fake Player AI)

В плагине Rounds реализована полностью автономная серверная система фальшивых игроков (Fake Players) на базе нативного NMS Minecraft (`net.minecraft.server.level.ServerPlayer`). Боты функционируют исключительно на серверных тиках без использования внешних плагинов-мостов (zero external bridge) и клиентских бот-процессов.

---

## 1. Архитектура NMS и жизненный цикл сущности (Entity Lifecycle)

### 1.1. Инициализация и сетевой уровень
- Для каждого бота инстанциируется нативный экземпляр `ServerPlayer` с фиктивным профилем `GameProfile(UUID, name)`.
- **Сетевые заглушки:**
  - `NoopConnection`: кастомный фиктивный сетевой пайплайн, отбрасывающий любые исходящие пакеты, что сводит к нулю сетевую нагрузку на клиентский трафик.
  - `FakeConnection`: симуляция клиентского сетевого подключения, гарантирующая корректную регистрацию бота в `PlayerList` Minecraft.
- Боты зарегистрированы в серверном `PlayerList`, отображаются в Tab-листе игроков, скорбордах и системах таргетинга точно так же, как живые игроки.
- **Масштабируемый спавн:** поддерживается пакетный спавн до 500 ботов одновременно через команды `/rbot spawn count <N>` с автоматической балансировкой по командам.
- **Гарантированный деспавн и освобождение памяти (Zero Memory Leak):** при завершении игры, остановке раунда или удалении ботов (`despawnBot`/`despawnAll`) полностью разрываются все ссылки во всех менеджерах плагина (`PlayerDataManager.unregisterPlayer`, `GameManager.onPlayerQuit`, `CardManager`, `CardGUI`, `RoundsEntities`, `BlockListener`), NMS-сущность безопасно отключается и сбрасывается (`discard()`, `removePlayerImmediately`), обнуляется навигационная сетка `ArenaNavMesh` и вызывается сборка мусора `System.gc()`, гарантируя возврат оперативной памяти операционной системе хостинга.

### 1.2. Динамическое обновление ссылок при респавне (Respawn Safety)
В Spigot/Paper при гибели и возрождении игрока экземпляр `ServerPlayer` пересоздается движком с новым физическим объектом. Для предотвращения обращения к устаревшим (dead/invalid) ссылкам класс `FakeBot` реализует динамическое получение сущностей:
```java
public Player getBukkitPlayer() {
    Player p = Bukkit.getPlayer(bukkitPlayer.getUniqueId());
    if (p != null) this.bukkitPlayer = p;
    return this.bukkitPlayer;
}

public ServerPlayer getNmsPlayer() {
    DedicatedServer nmsServer = ((CraftServer) Bukkit.getServer()).getServer();
    ServerPlayer sp = nmsServer.getPlayerList().getPlayer(bukkitPlayer.getUniqueId());
    if (sp != null) this.nmsPlayer = sp;
    return this.nmsPlayer;
}
```
При событии `PlayerRespawnEvent` менеджер `BotManager` вызывает `bot.updatePlayer(event.getPlayer())`, синхронизируя актуальный экземпляр.

### 1.3. Тиковый цикл ИИ (`BotAI`)
У каждого активного бота запущен персональный тиковый процесс `BotAI` (интервал 1 тик):
```java
this.ai = new BotAI(this);
this.ai.runTaskTimer(manager.getPlugin(), 1L, 1L);
```
Тиковый цикл последовательно выполняет:
1. Проверку состояния раунда и фазы игры (`GameState.CARDS`, `GameState.ACTIVE`).
2. Проверку физического полета на батутах и воздушного контроля.
3. Сканирование поля зрения и обнаружение противников с учетом честной видимости.
4. Тактическое позиционирование: засады за углом, поиск укрытий, отступление или лечение.
5. Боевые маневры: стрейф, джокинг, уклонения, прицеливание и стрельбу.
6. Навигацию по вейпоинтам сетки `ArenaNavMesh`, паркур через ямы и обход стен.
7. Обновление таймеров перезарядки, кулдаунов способностей и парирования щитом.

## 2. Система уровней сложности (Difficulty Levels 1..10)

Уровень боевого мастерства каждого бота задается целым числом $L \in [1..10]$:
- **Коэффициент навыка:** `factor = level / 10.0` (диапазон от `0.10` на 1 уровне до `1.00` на 10 уровне).
- **Шаг масштабирования:** ровно **+10%** боевой эффективности за каждый уровень сложности.
- **Динамический реролл:** в начале каждого нового раунда вызывается `botManager.randomizeBotLevels()`, заново перераспределяя случайный уровень всем активным ботам.

### Математические формулы масштабирования характеристик:
| Параметр | Формула | Уровень 1 (`factor=0.1`) | Уровень 10 (`factor=1.0`) |
| :--- | :--- | :--- | :--- |
| **Разброс прицеливания (Aim Error)** | `(1.2f / factor) * 0.90f` | $\pm 10.8^\circ$ (промахи) | $\pm 1.08^\circ$ (снайперская точность) |
| **Скорость доводки прицела (Turn Speed)** | `(6.0f + 8.0f * factor) * 1.10f` | $7.48^\circ$ / тик (плавная доводка) | $15.4^\circ$ / тик (быстрый флик) |
| **Кулдаун между выстрелами** | `round((4 + (1.0 - factor) * 14.0) * 0.90)` | 15 тиков (редкий огонь) | 4 тика (максимальный DPS) |
| **Скорость стрейфа (Agility)** | `(0.12 + 0.04 * factor) * 1.10` | 0.136 блоков/тик | 0.176 блоков/тик |
| **Частота смены направления стрейфа** | зависит от стиля игры | каждые 50–85 тиков (2.5–4.2 сек) | каждые 26–50 тиков (1.3–2.5 сек) |
| **Максимальная дистанция стрельбы** | `10.0 + 30.0 * factor` | 13.0 метров | 40.0 метров |
| **Шанс дальнего выстрела (>8м)** | `rnd < factor` | 10% шанс | 100% уверенная стрельба |
| **Блок щитом при получении урона** | `rnd < factor` | 10% шанс блока | 100% уверенный блок |
| **Парирование урона батута щитом** | `level >= 5 && rnd < 0.50` | 0% (всегда получает урон 20%) | 50% шанс парировать урон батута |
| **Шанс ошибки паркур-прыжка** | ступенчатый тир (-10%) | 27% (ур. 1–3), 18% (ур. 4–7) | 0% (ур. 10, безошибочный прыжок) |
| **Шанс ошибки воздушного контроля** | ступенчатый тир (-10%) | 9% (ур. 1–3), 6.3% (ур. 4–7) | 0.9% (ур. 10) |

## 3. Боевые архетипы личности (Bot Playstyles)

В начале каждого раунда в методе `BotAI.onRoundStart()` боту случайным образом присваивается один из четырех боевых архетипов:

### 3.1. `AGGRESSIVE_FLANKER` (Агрессивный фланкер)
- **Дистанция боя:** 5.0–9.0 метров. Стремится обойти противника сбоку или с тыла.
- **Патрулирование:** патрулирует по широкому внешнему периметру арены (15–22 блока от центра).
- **Маневры:** умеренная частота смены направления (34–58 тиков), прыжки для уклонения с шансом `0.015 * factor` при получении обстрела.

### 3.2. `TACTICAL_SNIPER` (Тактический снайпер)
- **Дистанция боя:** 16.0–24.0 метров. Если противник подходит ближе 10 метров, немедленно переходит в тактическое отступление (`CombatTactic.RETREAT`).
- **Патрулирование:** занимает угловые позиции, возвышенности и верхние ярусы арены.
- **Маневры:** не совершает прыжков во время прицеливания ради идеальной линии огня.

### 3.3. `DEFENSIVE_TURTLE` (Оборонительная черепаха)
- **Дистанция боя:** средняя дистанция 10.0–15.0 метров.
- **Оборона:** при опустошении обоймы (`ammo <= 0`) или получении урона закрывается щитом либо уходит в безопасное укрытие.
- **Синергии:** идеально реализует карты исцеления на блоке (`Heal`), вампиризм и зарядку выстрела (`Empower`).

### 3.4. `ERRATIC_BRAWLER` (Непредсказуемый боец ближнего боя)
- **Дистанция боя:** агрессивная дуэль в упор на дистанции 7.0–11.0 метров.
- **Джокинг:** частая непредсказуемая смена вектора стрейфа каждые 26–46 тиков с плавной интерполяцией скорости.
- **Уклонения:** тактические прыжки (`velY = 0.38`) прямо во время ведения огня с вероятностью `0.025 * factor`.

## 4. Честное зрение и обнаружение противников (Anti-Wallhack Detection)

Боты не видят сквозь непрозрачные блоки и подчиняются строгим законам физики зрения:
1. **Конус обзора (FOV):** 140° (по 70° в каждую сторону от взгляда). Рассчитывается через скалярное произведение вектора направления взгляда и вектора на цель:
   ```java
   Vector toTarget = targetEye.toVector().subtract(botEye.toVector()).normalize();
   Vector dir = botEye.getDirection().normalize();
   double dot = dir.dot(toTarget);
   double angle = Math.toDegrees(Math.acos(Math.max(-1.0, Math.min(1.0, dot))));
   if (angle > FOV_HALF_ANGLE_DEG) return false;
   ```
2. **Максимальная дальность обнаружения:** 60 блоков (`MAX_VISION_DISTANCE_SQ = 3600.0`).
3. **Зона ближнего слуха (Footstep Proximity):** 2.5 метра. В пределах этого радиуса бот способен услышать шаги противника даже со спины, если между ними нет глухой стены.
4. **Трассировка луча прямой видимости (Line of Sight):** вызов `botPlayer.hasLineOfSight(target)` обязателен. Любой непрозрачный твердый блок исключает визуальное обнаружение.

## 5. Реакция на входящий огонь (Damage Direction Awareness)

При получении урона бот определяет координаты стрелка через метод `onAttacked(Location origin, UUID attackerId)`:
1. **Дебаунсинг:** реакция вызывается не чаще одного раза в 250 мс для защиты от спама тиков.
2. **Шанс реакции:** равен `smartChance = getSmartBehaviorChance()`.
3. **Угловая погрешность прицела:** бот вычисляет углы к источнику выстрела и накладывает погрешность в зависимости от уровня интеллекта:
   ```java
   float maxError = (float) ((1.0 - smartChance) * 90.0);
   float yawError = (ThreadLocalRandom.current().nextFloat() * 2f - 1f) * (maxError * 0.5f);
   float pitchError = (ThreadLocalRandom.current().nextFloat() * 2f - 1f) * (maxError * 0.3f);
   ```
   - На уровне 10 погрешность составляет не более $\pm 4.5^\circ$ (мгновенный точный захват стрелка).
   - На уровнях 1–2 погрешность достигает $\pm 45^\circ$.
4. **Плавная доводка взгляда:** разворот выполняется естественным образом через сглаженную интерполяцию поворота шеи и корпуса (без мгновенной 0-тиковой телепортации взгляда).

## 6. Настойчивость преследования (Pursuit Tenacity)

При потере прямой видимости (враг скрылся за препятствием) бот переходит в режим преследования:
1. **Шанс продолжения преследования:** вероятность не бросить преследование цели рассчитывается по формуле `Math.min(1.0, (getSmartBehaviorChance() * 1.20) * 1.15)`:
   - **Уровни 1–2:** **69.0%**
   - **Уровни 3–4:** **82.8%**
   - **Уровни 5–7:** **96.6%**
   - **Уровни 8–10:** **100%**
2. **Тайм-аут преследования (`PURSUIT_TIMEOUT_TICKS = 120`):** бот упорно преследует последнюю известную точку цели в течение 6.0 секунд.
3. При достижении точки (`distXZ <= 1.2`) бот останавливается на 25 тиков и сканирует сектор по сторонам (`searchScanYaw`). Если за 120 тиков цель не найдена, бот переключается на исследовательский патруль арены.

## 7. Тактические укрытия, засады за углом и лечение

1. **Поиск укрытия (Cover Search):**
   - Активируется при падении здоровья $\le 20\%$ HP (или $\le 25\%$ при наличии карты `Heal`).
   - Использует предвычисленные узлы `coverNodes` навигационной сетки `ArenaNavMesh` либо радиальный поиск лучами в радиусе 4.0–6.5 блоков по 8 направлениям.
2. **Поведение в укрытии:**
   - При наличии карты `Heal` поднимает щит каждые 20 тиков для безопасного восстановления HP.
   - При наличии карты `Chameleon` замирает неподвижно для включения полной невидимости.
3. **Тактическая засада за углом (Ambush Trap):**
   - Если цель скрылась за углом коридора, бот с вероятностью `smartChance` занимает позицию засады:
     - Не упирается лицом в стену: алгоритм вычисляет свободный угол коридора (`ambushHoldYaw`), направляя прицел в сектор предполагаемого появления врага.
     - Заранее поднимает щит, накапливая бонус карты `Empower`.
     - Приседание на Shift отключено как избыточное (игровые ники скрыты глобально).
     - При появлении цели моментально производит усиленный выстрел из засады.
     - При истечении таймера засады (`ambushTicksLeft <= 0`) бот плавно снимает засаду и возобновляет патруль.

## 8. Физический движок и трехмерная навигация (`FakeBot.moveRel`)

1. **Интеграция движения и горизонтальная инерция:**
   - Перемещение осуществляется нативным NMS-вызовом `sp.move(MoverType.SELF, new Vec3(moveX, finalVelY, moveZ))`.
   - Гравитация: `velY = Math.max(velY - 0.08, -3.92) * 0.98`.
   - **Человеческая горизонтальная инерция (Smooth WASD Momentum):** скорости интерполируются с ускорением `accel = onGround ? 0.42 : 0.28`. Устранены резкие 1-тиковые рывки и телепортации скорости.
   - **Плавная доводка прицела:** экспоненциальная кривая сглаживания `turnFactor = 0.32 + 0.16 * factor`.

2. **Преодоление ступеней и блочных лестниц (Staircase Recognition & Auto-Jump +30%):**
   - Алгоритм `isBlockStaircase(loc, heading, dist)` классифицирует 1-блочные подъемы рельефа и лестницы как проходимые ступени при наличии запаса высоты >= 1.8м над препятствием, не путая их со сплошными стенами.
   - Дистанция упреждения прыжка перед ступенью увеличена на 30% (с 0.55 до 0.72 блока), а импульс ускорения вперед при преодолении препятствия усилен на +30% (`velX/velZ * 1.30`), что исключает застревание на блочных подъемах.
   - **Плавный спуск по ступеням:** если бот сходит с уступа и под ногами на расстоянии 1.1м есть твердый пол, ему задается стабильная скорость спуска `velY = -0.32`, исключая зависание в воздухе.
   - **Защита от зацикливания:** счетчик `consecutiveJumpAttempts` прерывает прыжки при 3 безуспешных попытках, переводя бота на обходной курс.

3. **Защита от стакинга сущностей (Anti-Stacking):**
   - Если бот оказывается на голове другого игрока (`dy` от -1.95 до -0.4, `distXZ < 0.64`), генерируется латеральный импульс сброса в сторону величиной `0.32`, не позволяя игрокам стоять башней друг на друге.

4. **Паркур через пропасти 1–4 блока (`findParkourLandingFloor`):**
   - На ходу сканирует пространство перед ногами на дистанцию до 4.2м (масштабируется карточками скорости и высокого прыжка).
   - При обнаружении безопасной площадки бот совершает спринт-прыжок (`velY = 0.42..0.46 * jumpMult`, `impulse = (0.16 + 0.08 * factor) * speedMult`).
   - Шанс ошибки (недопрыг): 30% на ур. 1–3, 20% на ур. 4–7, 10% на ур. 8–9, 0% на ур. 10.
   - **Защита от падений в пропасть (Cliff Drop Prevention):** глубокие обрывы признаются непроходимыми, если впереди нет безопасной платформы.

## 9. Навигация в узких пространствах, красные зоны и обход стен

1. **Красные зоны комнат 3x3–5x5 и тупиков 1x1x1 (Red Zones Blacklist):**
   - **Чёрный список комнат (3x3, 4x4, 5x5):** при выходе из замкнутой тупиковой комнаты бот помечает ее центр как красную зону на **60 секунд** (`RedZone`). Во время патрулирования и поиска вход в красную зону категорически блокируется, исключая бесконечный повторный заход. При нахождении внутри зоны выход из нее наружу всегда разрешен (проверка направления вектора от центра). Вход в красную зону разрешен исключительно при активной боевой погоне за врагом (`currentTarget != null`).
   - **Приоритет вертикального выхода из комнат:** перед выбором двери `findRoomExit` сканирует окружение на 360° на наличие блочных лестниц (`isBlockStaircase`) и паркур-подъемов на второй этаж, отдавая им высший приоритет над дверным выходом.
   - **Одиночные карманы 1x1x1 (`checkSinglePocketEscape`):** при обнаружении трех глухих стен вокруг блока бот моментально поворачивает голову и корпус в сторону открытого выхода (без медленного вращения в угол), фиксирует курс выхода на 35 тиков (1.75 с) и помечает точку как красную зону на **60 секунд**.
   - **Защита от залипания и осмотра стен/углов:** при сближении с препятствием бот мгновенно отворачивается со скоростью до 45°/тик (вместо медленного 12° скольжения взгляда по стене) и временно обнуляет поступательное движение вперед до завершения разворота, предотвращая утыкание в угол соединенных блоков (`isInsideCorner`).
   - **Бесшовное преодоление ступеней и лестниц из блоков:** алгоритм `isBlockStaircase` анализирует блочные перепады с высотой подъема <= 1 блок и достаточным запасом высоты потолка. Увеличенный импульс толчка вперед (0.24) и поддержка инерции во время подъема (`jumpAscentTicks`) гарантируют чистое запрыгивание на первую и последующие ступени без ложного отката назад.
   - **Поиск открытых проемов (`findRoomExit`):** сканирование на 360° с шагом 22.5° находит самый глубокий дверной проем, фиксируя курс выхода на 45 тиков.

2. **Обход ровных стен без колебаний (Persistent Wall Detour & Dynamic Corner Bypass):**
   - При обнаружении глухой стены алгоритм `findClearDirection` выбирает сторону обхода (-1 для левой, +1 для правой) и сохраняет ее в переменной `wallDetourSign`.
   - Все последующие проверки отклонений в `findClearDirection` тестируют углы в направлении `wallDetourSign` в первую очередь, полностью исключая колебания и пинг-понг вдоль одной стены.
   - Курс обхода фиксируется на **35 тиков** (~1.75 с, дистанция 5-6 метров).
   - **Динамический выход:** на каждом тике вызывается `isDirectionClear(myLoc, desiredHeading, 2.0)`. Как только угол стены пройден, фиксация немедленно сбрасывается в 0, `wallDetourSign` обнуляется, и бот сразу устремляется к цели.
   - В `ArenaNavMesh.getNearestNode(loc)` добавлена проверка прямой проходимости в радиусе 6 метров (`isWalkableConnection`), предотвращающая выбор стартового навигационного узла за противоположной стороной стены.

## 10. Умные батуты (Jump Pads) и блоки подъема (Up-Blocks)

1. **Игровая логика батутов в Rounds:**
   - Батут наносит игроку и боту 20% урона от максимального здоровья и подбрасывает вверх.
   - **Задержка выбора в начале раунда:** намеренный выбор батута алгоритмом заморожен на случайное время от 3 до 15 секунд (математическое среднее 5.0 секунд), что исключает случайные прыжки со спавна на старте раунда.
   - **Случайное срабатывание:** при случайном попадании на батут во время боя или патруля он срабатывает штатно.

2. **Парирование урона батута щитом (Shield Parry Jump):**
   - Боты с уровнем интеллекта 5 и выше (`level >= 5`) с вероятностью **50%** поднимают щит за 10–20 тиков до падения на батут.
   - При успешном парировании бот получает полный импульс взлета, но урон от батута полностью поглощается (0 урона) со звуком блокирования щитом.

3. **Защита от зацикливания на одиночном центральном блоке в кольце батутов:**
   - Блоки батутов никогда не признаются ступенями для запрыгивания.
   - В `isDirectionClear`, если перед ногами обнаружен батут, но за ним есть твердая внешняя платформа (`hasParkourTargetAhead`), направление признается открытым, и бот совершает паркур-прыжок через батут на внешнюю арену.
   - Методы `findSafeLandingTarget` и `findNearbySolidPlatform` требуют ширину площадки `breadth >= 3` и исключают блоки, примыкающие к батутам (`isLocationTouchingJumpBlock`). Одиночный центральный 1-блочный остров никогда не выбирается как точка приземления. Если бот запускается с центра, вектор наведения ориентируется во внешние сектора арены.

4. **Естественный контроль полета (Air Control):**
   - В полете бот непрерывно подруливает к целевой безопасной платформе со скоростью до 0.24 блоков/тик.
   - Поддерживает двойные прыжки через промежуточные площадки при дальности полета свыше 8-10 блоков.
   - Гравитация и перемещение вызываются на каждом тике полета, исключая зависания в воздухе.
   - Шанс ошибки приземления: от 10% на ур. 1–3 до 1% на ур. 10.

5. **Блоки вертикального подъема (Up-Blocks / Elevators):**
   - Автоматически находят безопасную платформу выхода верхнего этажа (`findUpBlockExitPlatform`), получают горизонтальный толчок на этаж и спускной импульс `velY = -0.32`.

## 11. Синергия карточек улучшения и способностей на блоке

Боты анализируют активные карточки в `PlayerData` и меняют тактический рисунок боя:
1. **Пила (`Saw`):** при поднятии щита переходит в форсированный штурм (`speed = 0.46`), сокращая дистанцию до врага (< 2.8 блока) для нанесения урона огненным кольцом.
2. **Способности на блоке щитом:**
   - `Implode`: блок на дистанции 4–7м для затягивания врага во взрыв.
   - `Silence` / `SilenceAura`: блок в радиусе 5м для глушения стрельбы и способностей цели.
   - `EMP`: блок при сближении ближе 6м для наложения замедления.
   - `Overpower`: блок в упор для нанесения процентного урона.
   - `BombOnBlock` / `ShieldCharge`: спавн бомб и дополнительный запас парирования.
   - `Teleport`: тактический телепорт при блоке для уклонения или сближения.
   - `Empower`: если кулдаун стрельбы $\le 1$ тик, кратковременно поднимает щит перед выстрелом, накапливая бонус урона.
   - `Heal`: при HP < 75% регулярно поднимает щит в укрытии для самоисцеления.
   - `Shockwave`: отбрасывает цель ударной волной на дистанции < 4.5м.
   - `HomingOnBlock`: активирует блок для временного самонаведения пуль.
   - `TacticalReload`: активирует блок при пустой обойме (`ammo <= 0`) для моментальной перезарядки.
3. **Модификаторы движения:** карточки прыжка позволяют ботам распознавать препятствия в 2–3 блока как преодолимые; карточки скорости пропорционально ускоряют стрейф и маневры.
4. **Стойки:** снайперская стойка (`Grow`), сближение в ауру (`LifestealAura`), маскировка в засаде (`Chameleon`).

## 12. Фаза драфта карт (`GameState.CARDS`)

1. **Полная неподвижность и неуязвимость:**
   - Во время выбора карт все игроки и боты полностью обездвижены: `PlayerMoveEvent` отменяет изменение X/Y/Z (сохраняя вращение камеры), скорость обнуляется, а метод `FakeBot.moveRel` блокируется.
   - Любой входящий урон блокируется на приоритете `LOWEST`, здоровье восстанавливается до 100%, огонь гасится.
   - Стрельба из пушки, блокирование щитом, урон и запуск от батутов и блоков подъема полностью отключены.
2. **Автоматический выбор карты ИИ:**
   - Метод `findBestCardSlot(Inventory inv)` сканирует открытое GUI и оценивает карты по шкале редкости:
     `LEGENDARY` (5) > `EPIC` (4) > `RARE` (3) > `UNCOMMON` (2) > `COMMON` (1).
   - С вероятностью `factor` бот выбирает карту наивысшей редкости; в противном случае берет случайную доступную карту.
   - Время размышления составляет от 1 до 10 секунд (в среднем 3–5 секунд), симулируя естественный выбор живого игрока.

## 13. Высокопроизводительная оптимизация (Стабильные 20 TPS при 192+ и до 500 ботов)

1. **Иммутабельная матрица профилей (`CombatProfile`):**
   - Все параметры точности, наведения, кулдаунов и стрейфа предвычисляются в массиве `CombatProfile[11][4]` при загрузке класса. Доступ выполняется за $O(1)$ без выделения объектов в памяти на тике.
2. **Шахматное чередование поиска целей (Tick Interleaving):**
   - Тяжелые проверки видимости цели чередуются между ботами по условию `(tickCount + entityId) % 2 == 0`, сокращая количество запросов `RayTrace` к серверу в 2 раза.
3. **Троттлинг сканирования комнат:**
   - Поиск дверных проемов ограничен кулдауном в 30 тиков (`roomExitCooldown`), шаг сканирования составляет 30°.
4. **Навигационная сетка арены (`ArenaNavMesh`):**
   - Граф вейпоинтов строится один раз в начале раунда (~1 мс на 120–160 узлов) и используется всеми ботами совместно. Обеспечивает мгновенный Dijkstra-поиск обходных путей с учетом индивидуальной репутации (`pathReputation`).
5. **Адаптивный 4-уровневый LOD тикрейта ИИ:**
   - LOD 1 (0–12м от врагов): 20 TPS (каждый тик).
   - LOD 2 (12–25м от врагов): 10 TPS (каждые 2 тика).
   - LOD 3 (25–40м от врагов): 7 TPS (каждые 3 тика).
   - LOD 4 (>40м, либо >25м при 50+ активных ботах): 5 TPS (каждые 4 тика).
   - Расчет дистанции исключает союзников: боты, стоящие рядом с союзниками далеко от врагов, корректно уходят в энергосберегающий режим. Физика движения и гравитация сохраняют непрерывность на каждом тике.
6. **Двухэтапная фильтрация целей (FOV и Distance-First в `findVisibleTarget`):**
   - Вместо затратной трассировки лучей через блоки мира (`hasLineOfSight`) для всех сущностей арены цели сначала фильтруются легкими $O(1)$ математическими проверками:
     1) Дистанция меньше расстояния до текущего наилучшего кандидата (`distSq < bestDistSq`).
     2) Попадание в конус зрения 140° через скалярное произведение вектора взгляда и вектора на цель.
   - Тяжелый NMS-метод `hasLineOfSight` вызывается исключительно для кандидатов, прошедших предварительный отбор, отсекая свыше 99% трассировок лучей в массовых боях.
   - Проверка союзников `isTeammate` для ботов выполняется через прямое сравнение назначенной команды `bot.getAssignedTeam()`, минуя обращение к картам игроков и UUID.
7. **Пакетная синхронизация команд и исключение ботов из Scoreboard ($O(1)$):**
   - При старте раунда (`startRound`) и распределении 192+ ботов по командам вызов пересчета скорбордов выполняется пакетом ровно один раз (`applyTeamColor(p, false)` с финальным вызовом `refreshTeamScoreboards()`), предотвращая каскадные вызовы $O(N \cdot T)$ и зависание сервера (watchdog timeout).
   - Боты (`FakeBot`) не имеют клиентского сетевого подключения и исключены из хранения в `playerScoreboards`, исключая бесполезное выделение объектов скорборда в памяти.
   - В `setupTeamsOnScoreboard` поиск команды записи оптимизирован до прямого $O(1)$ (`sb.getEntryTeam(name)` и `sb.getTeam(name)`) без пересоздания и обхода коллекций команд `sb.getTeams()`.
8. **Оптимизация анти-стакинга в `FakeBot.moveRel`:**
   - Проверка сущностей для расталкивания фильтруется быстрыми проверками 1D bounding box (`Math.abs(dx) > 1.2 || Math.abs(dz) > 1.2`), исключая тяжелые вычисления расстояний на сотнях сущностей.

## 14. Балансировка и привязка к блокам шерсти команд на карте

- При спавне ботов плагин учитывает фактически установленные на арене шерстяные блоки команд (`joinBlocks`).
- Если на арене установлены блоки только определенных цветов (например, только Красной и Синей команд), боты распределяются исключительно в команды `RED` и `BLUE`.
- При попытке указать несуществующую на карте команду бот автоматически переназначается в доступную команду с наименьшим числом участников.

## 15. Полный справочник команд управления ботами

### Команды `/rbot`:
- `/rbot spawn`: спавнит одного бота со случайным именем, автоматической командой и случайным уровнем сложности (1..10).
- `/rbot spawn <N>` или `/rbot spawn count <N>`: массовый спавн до 500 ботов с автоматической балансировкой по командам.
- `/rbot spawn <name> [team] [1..10]`: спавн бота с конкретным именем, командой и уровнем.
- `/rbot despawn [name]`: удаление конкретного бота или всех ботов сразу (если имя не указано).
- `/rbot list`: вывод списка всех активных ботов с указанием их здоровья, команды, уровня сложности и боевого архетипа.
- `/rbot level <name> <1..10>`: установка уровня сложности конкретному боту.
- `/rbot level all <1..10>`: установка уровня сложности всем активным ботам.
- `/rbot <name> level <1..10>`: альтернативный синтаксис настройки уровня.
- `/rbot <name> strategy <flanker|sniper|turtle|brawler>`: принудительная смена архетипа поведения бота.

### Отладочные команды `/rdebug bot`:
- `/rdebug bot spawn <count>`: спавн указанного количества ботов.
- `/rdebug bot clear`: деспавн всех ботов на сервере.
- `/rdebug bot list`: диагностический список сущностей ботов.
- `/rdebug bot level <1..10>`: установка глобального уровня для последующих спавнов.

## 16. Визуальные эффекты боя, подсветка и отображение никнеймов

1. **Формат никнеймов и индикация уровней ботов:**
   - Отображение в Tab-листе и над головой: `<число>♥ <Ник>` для игроков и `<число>♥ <Ник> [L<уровень>]` для ботов.
   - Тег уровня бота расположен строго после его имени, выделен жирным шрифтом в командном цвете (`§l[L1]`).
   - Число сердец рассчитывается пропорционально максимальному здоровью и округляется вверх.
2. **Командная видимость никнеймов (Team-Only Nametags):**
   - Во время активного раунда никнеймы противников полностью скрыты от глаз игроков (`Team.OptionStatus.FOR_OWN_TEAM` / `NEVER`). Игроки видят только своих союзников.
   - Наблюдатели (Spectators) и погибшие игроки видят никнеймы всех участников боя.
3. **Визуальная отдача при попадании (Combat Hit Feedback):**
   - При попадании пули по врагу вызывается `victim.playHurtAnimation(yaw)`, окрашивающий его модель в красный цвет и наклоняющий её от вектора выстрела.
   - Игрок, получивший урон, видит наклон камеры и плавную красную виньетку по краям экрана (`WorldBorder` warning).
4. **Ограничение подсветки и тиканье эффектов FakeBot:**
   - Карта «Марк был хороший» подсвечивает врагов максимум на 10 секунд (200 тиков) после отдаления.
   - У `FakeBot` реализовано тиканье эффектов зелий, благодаря чему подсветка и замедления корректно истекают по таймеру.
