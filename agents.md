# AGENTS.md — Инженерные стандарты и архитектурный протокол плагина Rounds

Этот документ определяет строгие правила архитектуры, стандарты кодовой базы, исчерпывающую спецификацию алгоритмов ИИ-ботов и протоколы валидации для любого ИИ-агента или разработчика, работающего с репозиторием **Rounds-MinecraftPlugin**.


## 1. Фундаментальные принципы и стек

1. **Версионная совместимость и байткод (Java 17 Target):**
   - Весь код обязан компилироваться строго в байткод **Java 17** (`major version: 61`).
   - Конфигурация компилятора в `build.gradle.kts`:
     ```kotlin
     tasks.withType<JavaCompile> {
         options.release.set(17)
     }
     ```
   - Тулчейн модулей: `rounds-core` и `rounds-api` используют toolchain Java 17, а NMS-модули новейших серверов (Purpur 26.2) могут использовать JDK 25 для линковки. Весь код компилируется строго в байткод **Java 17** (`major version: 61`, `options.release.set(17)`).
   - Classpath ordering: `paper-api:1.20.4` всегда ставится ПЕРВЫМ в classpath, чтобы сохранять Bukkit-константы 1.20.4 (`Attribute.GENERIC_MAX_HEALTH`, `Particle.EXPLOSION_HUGE`), избегая конфликтов с переименованными API в новых версиях.

2. **Единый автономный плагин (Zero External Bridge):**
   - Боты являются частью основного плагина (`com.rounds.bot.*`, `com.rounds.nms.*`).
   - Никаких внешних плагинов-мостов (`RoundsBotBridge`) или межплагинной рефлексии.
   - **Изоляция NMS (NmsBridge):** все прямые обращения к `net.minecraft.*` и `org.bukkit.craftbukkit.*` запрещены в `rounds-core` и изолированы за стабильным интерфейсом `com.rounds.nms.NmsBridge` (реализация `com.rounds.nms.impl.NmsBridgeImpl`, фабрика `NmsBridgeLoader`). Версионные модули по всем релизным версиям 1.20.4 - 26.3 сгруппированы в директории `rounds-nms/`: `rounds-nms1204` (paperweight-userdev, reobf в рантайм-маппинги v1_20_R3, инъекция протокол-атрибутов Connection.ATTRIBUTE_*), `1205`, `1206`, `121`, `1211`, `1213`, `1214`, `1215` (`PacketSendListener`-листенеры), `1216`, `1217`, `1218`, `1219`, `12110`, `12111`, `2611`, `2612`, `262`, `263` (`ChannelFutureListener`-листенеры; disconnect через `DisconnectionReason`/`DisconnectionDetails` в 26.x). Версия 1.21.2 недоступна у PaperMC upstream и не собирается. Минималистичный универсальный `FakeConnection` (только `tick()` + `send(Packet)`) исключает необходимость версионных disconnect-оверлоадов. Каждый модуль собирает финальный артефакт по маске `RoundsPlugin-<версия>-v1.9-byMr712.jar`; артефакт работает на Paper И Purpur своей версии Minecraft. При отсутствии моста под текущую версию плагин не падает: боты, спавн фейк-игроков и spectator glow отключаются с предупреждением в логе.

3. **Соблюдение игровой логики (Game Rules):**
   - В мини-игре Rounds **НЕТ ванильного урона от падения**. Любой ванильный расчет урона от падения (`fallDistance - 3.0`) строго запрещен.
   - Урон от батутов рассчитывается как процент от максимального здоровья (`jump-block.damage-percent`, 20% по умолчанию).
   - Перед вызовом `player.damage(...)` обязательно вызывается `player.setNoDamageTicks(0)`, чтобы тики неуязвимости Minecraft не блокировали игровой урон.
   - **Фаза выбора карт (`GameState.CARDS`) и пауза окончания раунда (`GameState.ROUND_END`):** При окончании раунда перед переходом к драфту карт выдерживается 3-секундная (60 тиков) пауза покоя: скорость обнуляется, игроки и боты полностью обездвижены (`PlayerMoveEvent` отменяет изменение X/Y/Z, сохраняя вращение камеры, `FakeBot.moveRel` блокируется), стрельба и щит заблокированы. В 3D драфте карт (`CardDisplayManager`) действует 1.5-секундная защита от случайных кликов из боя. Во время драфта все игроки неуязвимы (`EntityDamageEvent` отменяется на приоритете LOWEST, здоровье восстанавливается до максимума, огонь тушится), урон и подбрасывание от блоков отключены.

4. **Стандарты документации и оформления (Documentation Guidelines):**
   - В документации (`readme.md`, `readme.en.md` и любых других markdown-файлах) **строго запрещено** использование любых эмодзи (никаких значков, символов или смайлов). Все заголовки, списки, описания способностей (включая карту «Коллапс / Implode») и блоков обязаны быть оформлены строго чистым текстом без эмодзи.
   - Любые изменения документации ведутся синхронно в `readme.md` и `readme.en.md`.
   - **Запрет горизонтальных разделителей:** В любых markdown-файлах (`.md`) репозитория строго запрещено использование горизонтальных разделителей из трех дефисов подряд на отдельной строке. Разделение блоков и разделов оформляется исключительно стандартными заголовками `#`, `##`, `###` и пустыми строками.

5. **Встроенный переключаемый скорборд (Built-in Dual Scoreboard):**
   - Включен по умолчанию (`builtin-scoreboard.enabled: true`), но автоматически выключается при наличии активного плагина TAB во избежание конфликтов; если отключен в `config.yml`, не отображается вовсе.
   - Автоматически переключается каждые 5 секунд между двумя экранами: Игровой скорборд (победы команд) и Скорборд характеристик (HP, урон, карты, пули, патроны).
   - Двойная буферизация целей (`r_obj_a` / `r_obj_b`) гарантирует отсутствие мерцания (zero flicker).
   - Автономность: параметры вычисляются непосредственно в коде плагина, работая без обязательной установки PlaceholderAPI.

6. **Визуальная боевая отдача при попадании (Combat Hit Feedback):**
   - При попадании по противнику вызывается `playHurtAnimation` (окрашивание 3D-модели в красный цвет и наклон от выстрела).
   - При получении урона игроком камера наклоняется в сторону источника урона и активируется красная виньетка ранения на экране (`WorldBorder` warning).

7. **Бесконечный лимит раундов (Unlimited Rounds):**
   - Количество раундов в команде `/rdebug rounds <N>` принимает любое положительное число ($N \ge 1$) без искусственных верхних порогов. Любые жесткие ограничения (`amount > maxRounds`) строго запрещены.

8. **Безопасность и отказоустойчивость драфта карт (Card Draft Resilience):**
   - **Автовыбор при таймауте:** При истечении времени выбора карты (`remaining <= 0`) кикать игрока с сервера (`p.kickPlayer`) строго запрещено во избежание слома матча и дисбаланса команд. Вместо этого вызывается автоматический выбор случайной карты из предложенных (`selectCard(p, randomIndex)`) с закрытием инвентаря игрока.
   - **Перенос строк описаний карт:** Для исключения выхода тултипа за пределы экрана все описания карт в GUI форматируются методом `Card.wrapText(desc, 38)` (~38 символов в строке) с сохранением цветов `ChatColor`.
   - **Безопасность консольных команд карт:** При выполнении команд из карт (`Card.apply`) имя игрока валидируется regex `^[a-zA-Z0-9_.]{3,32}$`, деструктивные команды (`op`, `deop`, `stop`) блокируются, а вызов принудительно оборачивается в синхронный таск Bukkit Scheduler.

9. **Стандарты производительности физики пуль (`RoundsEntities`):**
   - **Zero Allocation рейкастов:** Использование переиспользуемого вектора `Bullet.rayDir` для блочных трассировок `world.rayTraceBlocks`, исключающее создание временных объектов `Vector` в тиковом цикле.
   - **Оптимизация коллизий без `Math.sqrt`:** Определение попаданий капсульного хитбокса пули по игрокам обязано использовать сравнение квадратов расстояний (`distSq > maxDist * maxDist`).
   - **Снижение сетевой нагрузки трассеров:** Шаг трассера зафиксирован на `TRACER_STEP = 0.9`, а максимум точек — `TRACER_MAX_POINTS = 4`.
   - **Быстрый таргетинг самонаведения:** Самонаводящиеся пули ищут врагов исключительно перебором игроков текущего мира (`center.getWorld().getPlayers()`) в радиусе 30 метров, без тяжелых запросов по чанкам `getNearbyEntities`.

10. **Атрибуция убийств и честная статистика матча (Kill Attribution):**
    - Урон, применяемый мимо ванильного пайплайна урона (фоллбек `RoundsEntities.safeSetHealth` после отмены удара щитом, осколки Razorwire, TNT Skyfall), обязан регистрировать атакующего через `MatchStatsManager.recordLastDamager(victim, attacker)`; реестр хранит последнего атакующего 30 секунд и чистится на `onGameStart`/`onGameEnd`.
    - В `GameManager.onPlayerDeath` сначала используется ванильный `dead.getKiller()`, при отсутствии — последний атакующий из реестра; после обработки запись поглощается (`consumeLastDamager`), двойной счёт исключён.
    - Авто-смерть (`killRandomPlayer`) реализуется смертельным уроном через обычный пайплайн (`setNoDamageTicks(0)` + `victim.damage(1_000_000.0)`), чтобы карты-спасатели (Bullet Time, Second Wind, Phoenix) срабатывали штатно; маркер `pendingAutoDeaths` добавляется до смерти и списывается через 10 тиков, если жертва была спасена.
    - Убийство авто-смерти зачитывается ВСЕГДА случайно выбранному живому противнику другой команды (`findAutoDeathExecutioner`), независимо от последнего удара; единственная точка зачисления — блок обработчика смерти, а не тело жатки.
    - `kill @a` с консоли и «безавторные» смерти убийство никому не зачитывают.

11. **Спасательные карты без стакания (Non-Stacking Saves):**
    - Заряды спасений: Bullet Time — строго 1 раз за раунд (`bulletTimeUsedThisRound`), Second Wind — по `secondWindUses`, Phoenix — по `phoenixUses`.
    - Задержанный сброс неуязвимости Bullet Time выполняется для любого состояния `owner.isOnline()` (даже в момент смерти/респавна владельца), исключая «висячий» навсегда invulnerable-флаг — они не могут «стакаться».
    - Исключение в слушателе урона запрещено распространять: оно абортирует диспетчер `EntityDamageEvent` и весь вызов `hurt()` — жертвы перестают получать любой урон. Потенциально исключительные вызовы (razorwire и пр.) оборачиваются в `try/catch`.

12. **Устойчивость Razorwire (`LegendaryEffects.triggerRazorwire`):**
    - Позиции `center`/`tEye` проверяются `isFiniteLocation`; направление луча считается вручную по длине и отсекается при `< 1e-6` — защита от `IllegalArgumentException: x not finite` в `rayTraceBlocks`.
    - Каждый осколок залпа оборачивается собственным `try/catch`: один битый осколок не рушит весь залп и не прерывает обработку урона.

13. **Отладочная сессия (`/rdebug debug start ...`) триггерится в `startRound()`:**
    - Планированное включение (`startAt`) проверяется в начале КАЖДОГО нового раунда (`GameManager.startRound`), а не в `startGame()` — тот проходит один раз за игру и сразу сбрасывает счётчик раундов в 0.
    - Если план ставится на текущий PLAYING-раунд — сессия активируется немедленно.
    - Автостоп (`stopAt`) в `endRound` и ручной `/rdebug debug stop` завершают ТОЛЬКО логирование и закрывают дамп-файл; сама игра никогда не останавливается завершением дебага.

14. **Автономный HUD счета матча (`HudEngineCustomRealisation`):**
    - Встроенная реализация оверлея раундов (`com.rounds.hud.HudEngineCustomRealisation`) функционирует полностью автономно без внешнего плагина HUDEngine.
    - 100% 1:1 совместимость с ресурспаками: невидимый BossBar цвета `PINK`, шрифт `hudengine:hud`, динамическое смещение отрицательными пробелами `0xF2000 + dx`, шаг между квадратиками `BOX_STEP = 14` (3px отступ), полупрозрачность пустых квадратиков (70% transparency / 30% opacity), отключение тени на Paper 1.21.4+ через `ShadowColor.none()`.
    - Динамическое количество строк: оверлей отображает ровно столько строк квадратиков, сколько команд активно участвует в матче (2 команды = 2 строки, 3 = 3, 4 = 4), новые строки добавляются снизу без пустых промежутков при подключении новых команд.
    - Переключатель отображения (`screen-indicators.enabled: true` в `config.yml`, команда `/rdebug screenindicators on/off`): при включенном оверлее чат-блок победы в раунде со списком команд полностью подавляется (в чате отображается только финальная победа в игре).
    - Соблюдение лицензии MIT проекта HUDEngine от Nacvark.

15. **Интерактивные диалоговые подсказки входа и команды администратора (Join and Admin Prompts):**
    - Для игроков без команды (`NONE`) и новичков при входе на сервер во время идущей игры (`isGameStarted()`) и в начале каждого раунда в чат персонально выводится кликабельный блок с командой `/rdebug join` (RUN_COMMAND). В лобби до старта матча новичкам сообщение не выводится.
    - Для администраторов (`admin.rounds`, `rounds.admin` или OP) при входе на сервер и в конце игры (`endGame`) с задержкой в 3 секунды (60 тиков) персонально выводится блок быстрого старта с кнопками `/rdebug start` и `/rbot spawn`. В середине раундов админское сообщение не спамится.
    - Все ключи локализации находятся в секции `debug:` (`debug.join-prompt-*`, `debug.admin-prompt-*`).
    - Смена команды на `NONE` (`/rdebug setteam none`, наступление на блок выхода в лобби) полноценно освобождает слот команды, очищает кеш данных, переводит игрока в спектатора при активном матче и пересчитывает окончание раунда (`checkRoundEnd`), обновляя строки оверлея `HudEngineCustomRealisation.refresh()`.


## 2. Полная архитектура и спецификация боевых ботов (Fake Player AI)

В плагине реализована автономная серверная система фальшивых игроков (Fake Players) на базе нативного NMS Minecraft (`net.minecraft.server.level.ServerPlayer`), функционирующая полностью на серверном тике без использования внешних мостов или клиентских ботов.

### 2.1. NMS-сущность и сетевой уровень (Entity Lifecycle & Respawn Safety)

1. **Инициализация NMS:**
   - Для каждого бота создаётся нативный `ServerPlayer` с фиктивным профилем `GameProfile(UUID, name)` и кастомными сетевыми заглушками:
     - `NoopConnection`: фиктивный сетевой пайплайн, отбрасывающий исходящие пакеты для исключения сетевого оверхеда.
     - `FakeConnection`: симуляция клиентского подключения, гарантирующая добавление бота в `PlayerList` сервера.
   - Боты регистрируются в `PlayerList` Minecraft и отображаются в списке игроков, скорбордах и системах таргетинга точно так же, как настоящие игроки.
   - **Автоматический деспавн и полная очистка памяти (Zero Memory Leak):** при остановке игры (`GameManager.stopGame()`, `/rounds stop`, `/rdebug stop`), деспавне ботов (`despawnBot`, `despawnAll`, `despawnBots`) или перезагрузке выполняется глубокая очистка:
     - Разрыв всех GC-корней и удаление данных бота из всех менеджеров: `PlayerDataManager.unregisterPlayer` (очистка `cache`, `savedData`, кулдаунов `GunCooldowns`, `GunItem`, `LegendaryEffects`), `GameManager.onPlayerQuit` (очистка 16 карт состояния, задач и трекеров), `CardManager.cleanupPlayer`, `CardGUIListener.cleanupPlayer`, `RoundsEntities.clearPlayer`, `BlockListener.cleanupPlayer`.
     - Корректная утилизация NMS-сущности: вызовы `nmsPlayer.unRide()`, `nmsPlayer.closeContainer()`, `nmsPlayer.discard()`, моментальное удаление из срезов сущностей мира (`level.removePlayerImmediately(nmsPlayer, DISCARDED)`), отключение и обнуление сетевого соединения (`nmsPlayer.connection.disconnect(...)`, `connection = null`).
     - Завершение тикового таска и зануление внутренних ссылок в `BotAI.cleanup()` (сброс `currentTarget`, графов репутации и памяти зон) и `FakeBot.cleanup()`.
     - Сброс навигационной сетки арены (`navMesh = null`) и принудительный вызов `System.gc()`, гарантирующий немедленный возврат неиспользуемых страниц виртуальной памяти операционной системе хостинга (освобождение оперативной памяти в панели управления).
   - **Масштабируемый спавн (Bulk Limit до 500 ботов):** лимит разового спавна ботов через команды (`/rbot spawn count <N>`, `/rbot spawn <N>`) расширен с 50 до 500 ботов с автоматической балансировкой по командам.

2. **Динамическое обновление сущности при респавне:**
   - В Minecraft Spigot/Paper при смерти и респавне игрока экземпляр `ServerPlayer` пересоздается заново, а старый инстанс становится невалидным.
   - Класс [`FakeBot`](src/main/java/com/rounds/bot/FakeBot.java) **строго запрещает** кеширование ссылок на игрока и реализует динамические геттеры:
     ```java
     public Player getBukkitPlayer() {
         Player p = Bukkit.getPlayer(bukkitPlayer.getUniqueId());
         if (p != null) this.bukkitPlayer = p;
         return this.bukkitPlayer;
     }

     public ServerPlayer getNmsPlayer() {
         DedicatedServer nmsServer = ((CraftServer) Bukkit.getServer()).getServer();
         ServerPlayer sp = nmsServer.getPlayerList().getPlayer(bukkitPlayer.getUniqueId());
         if (sp != null) this.nmsPlayer = sp;
         return this.nmsPlayer;
     }
     ```
   - В `BotManager` при наступлении события `PlayerRespawnEvent` вызывается `bot.updatePlayer(event.getPlayer())`, синхронизируя актуальный экземпляр.

3. **Тиковый цикл искусственного интеллекта (`BotAI`):**
   - У каждого бота запускается собственный `BukkitRunnable` с интервалом в 1 тик:
     ```java
     this.ai = new BotAI(this);
     this.ai.runTaskTimer(manager.getPlugin(), 1L, 1L);
     ```
   - Цикл выполняет: проверку состояния игры -> проверку полета на батуте -> зрение и обнаружение целей -> засады / укрытия -> боевые маневры / преследование / патруль -> таймеры кулдаунов.

4. **Бесшовное подключение ботов посреди матча (Mid-Game Join Lifecycle):**
   - При спавне бота во время активного боя (`GameState.PLAYING`, `COUNTDOWN`): бот переносится в лобби, переводится в режим `ADVENTURE` с неуязвимостью, исключается из боевого цикла `BotAI` и регистрируется как `pendingCardJoiner`, не вмешиваясь в текущий раунд. В конце раунда бот вместе со всеми переносится на арену, получает драфт карт и полноценно вступает в бой со следующего раунда.
   - При спавне бота во время фазы драфта карт (`GameState.CARDS`): бот сразу появляется на командном спавне арены, получает выбор карточки улучшения и начинает бой в этом же раунде.


### 2.2. Система уровней сложности (Difficulty Levels 1..10)

Уровень интеллекта и боевой эффективности бота задаётся целым числом $L \in [1..10]$:
- **Фактор мастерства:** `factor = level / 10.0` (диапазон от `0.10` на 1 уровне до `1.00` на 10 уровне).
- **Шаг масштабирования:** ровно **+10%** боевой эффективности за каждый уровень.
- **Случайный реролл уровней:** при старте каждого нового раунда в `GameManager.startRound()` вызывается `botManager.randomizeBotLevels()`, заново перераспределяя случайный уровень каждому активному боту, создавая динамический игровой опыт.

#### Математические формулы масштабирования характеристик:
| Параметр | Формула | Уровень 1 (`factor=0.1`) | Уровень 10 (`factor=1.0`) |
| :--- | :--- | :--- | :--- |
| **Разброс прицеливания (Aim Error)** | `(1.2f / factor) * 0.90f` | $\pm 10.8^\circ$ (промахи) | $\pm 1.08^\circ$ (снайперская точность) |
| **Скорость доводки прицела (Turn Speed)** | `(6.0f + 8.0f * factor) * 1.10f` | $7.48^\circ$ / тик (плавная доводка) | $15.4^\circ$ / тик (быстрый флик) |
| **Кулдаун между выстрелами** | `round((4 + (1.0 - factor) * 14.0) * 0.90)` | 15 тиков (редкая стрельба) | 4 тика (максимальный DPS) |
| **Скорость стрейфа (Agility)** | `(0.12 + 0.04 * factor) * 1.10` | 0.136 блоков/тик (плавный стрейф) | 0.176 блоков/тик (быстрый ванильный стрейф) |
| **Смена направления (Juking)** | зависит от уровня и стиля игры | каждые 50–85 тиков (2.5–4.2 сек) | каждые 26–50 тиков (1.3–2.5 сек) |
| **Максимальная дистанция стрельбы** | `10.0 + 30.0 * factor` | 13.0 метров | 40.0 метров |
| **Шанс дальнего выстрела (>8м)** | `rnd < factor` | 10% шанс (-90% штраф) | 100% уверенная стрельба |
| **Блок щитом при уроне / в бою** | `rnd < factor` | 10% шанс успешного блока | 100% идеальное парирование |
| **Парирование урона батута щитом** | `level >= 5 && rnd < 0.50` | 0% (всегда получает урон 20%) | 50% шанс парировать урон батута |


### 2.3. Боевые архетипы личности (Playstyles)

В начале каждого раунда (`BotAI.onRoundStart()`) боту случайно присваивается один из четырех архетипов (`BotPlaystyle`), определяющий его тактические предпочтения:

```java
public enum BotPlaystyle {
    AGGRESSIVE_FLANKER,
    TACTICAL_SNIPER,
    DEFENSIVE_TURTLE,
    ERRATIC_BRAWLER
}
```

1. **`AGGRESSIVE_FLANKER` (Агрессивный фланкер):**
   - **Дистанция:** сближается на дистанцию 5.0–9.0 метров, стремясь обойти цель с фланга.
   - **Патрулирование:** патрулирует по широкому внешнему радиусу арены (15–22 блока от центра).
   - **Маневры:** умеренная частота смены направления (34–58 тиков), прыжки для уклонения с шансом `0.015 * factor` при получении обстрела.

2. **`TACTICAL_SNIPER` (Тактический снайпер):**
   - **Дистанция:** держит дистанцию 16.0–24.0 метров. Если противник сближается ближе 10 метров, немедленно отступает (`CombatTactic.RETREAT`).
   - **Патрулирование:** занимает угловые позиции и возвышенности на краях арены.
   - **Маневры:** не прыгает в бою (приоритет максимальной точности выстрела), держит ровную линию огня, стреляет с дальних дистанций.

3. **`DEFENSIVE_TURTLE` (Оборонительная черепаха):**
   - **Дистанция:** держит среднюю дистанцию 10.0–15.0 метров.
   - **Щит и укрытия:** при получении урона или при опустошении обоймы (`ammo <= 0`) поднимает щит (`CombatTactic.SHIELD`) или уходит за укрытие для безопасной перезарядки.
   - **Синергия:** идеально реализует карты `Heal` на блоке и `Empower`, заряжая выстрелы перед контратакой.

4. **`ERRATIC_BRAWLER` (Непредсказуемый боец ближнего боя):**
   - **Дистанция:** агрессивный бой на дистанции 7.0–11.0 метров.
   - **Джокинг:** динамичная смена направлений стрейфа каждые 26–46 тиков с плавной интерполяцией скорости.
   - **Уклонения:** тактические прыжки (`velY = 0.38`) прямо во время стрельбы с шансом `0.025 * factor` и кулдауном 2.5–4.5с.


### 2.4. Честное зрение без читов (Anti-Wallhack Detection)

Боты не видят игроков сквозь непрозрачные блоки и подчиняются строгим законам физики зрения:

1. **Параметры конуса зрения:**
   - **Угол обзора (FOV):** 140° (по 70° в каждую сторону от направления взгляда). Рассчитывается через скалярное произведение вектора взгляда и вектора на цель:
     ```java
     Vector toTarget = targetEye.toVector().subtract(botEye.toVector()).normalize();
     Vector dir = botEye.getDirection().normalize();
     double dot = dir.dot(toTarget);
     double angle = Math.toDegrees(Math.acos(Math.max(-1.0, Math.min(1.0, dot))));
     if (angle > FOV_HALF_ANGLE_DEG) return false;
     ```
   - **Максимальная дальность:** 60 блоков (`MAX_VISION_DISTANCE_SQ = 3600.0`).
   - **Зона ближнего слуха (Footstep Proximity):** 2.5 метра (`PROXIMITY_HEARING_DISTANCE_SQ = 6.25`). В радиусе 2.5м бот может услышать шаги противника даже за спиной, если между ними нет глухой стены.
   - **Трассировка луча (Line of Sight):** вызов `botPlayer.hasLineOfSight(target)` обязателен. Любой твердый блок полностью блокирует обнаружение.


### 2.5. Настойчивость преследования (Pursuit Tenacity) и тайм-аут

Когда цель выходит из зоны прямой видимости (прячется за угол или стену), бот переходит в режим преследования:

1. **Масштабирование шанса продолжения преследования (+15% относительно предыдущих значений, до 100%):**
   Базовый шанс умного поведения масштабируется по тирам сложности. Шанс не бросить преследование цели рассчитывается по формуле `Math.min(1.0, (getSmartBehaviorChance() * 1.20) * 1.15)`:
   - **Уровни 1–2:** шанс **69%** (было 60%)
   - **Уровни 3–4:** шанс **82.8%** (было 72%)
   - **Уровни 5–7:** шанс **96.6%** (было 84%)
   - **Уровни 8–9:** шанс **100%** (было 96%)
   - **Уровень 10:**  шанс **100%** (было 100%)

2. **Тайм-аут преследования (`PURSUIT_TIMEOUT_TICKS = 120`):**
   - Бот настойчиво бежит к `lastKnownTargetLoc` в течение **120 тиков** (6.0 секунд).
   - Если цель найдена до истечения 120 тиков, бой продолжается.
   - Если бот добежал до точки (`distXZ <= 1.2`), он останавливается и в течение 25 тиков сканирует пространство по сторонам (`searchScanYaw`).
   - Если за 120 тиков цель не обнаружена, бот переключается на исследовательский патруль (`executeSearchPatrol`).


### 2.6. Реакция на входящий огонь (Damage Direction Awareness)

При получении урона бот определяет координаты источника выстрела через метод `onAttacked(Location origin, UUID attackerId)`:
1. **Дебаунсинг:** реакция срабатывает не чаще одного раза в 250 мс для защиты от спама тиков.
2. **Шанс реакции:** равен `smartChance` (на низких уровнях бот может растеряться и проигнорировать направление).
3. **Расчет угла и погрешность:** бот вычисляет идеальные углы `idealYaw` и `idealPitch` к источнику выстрела и добавляет погрешность, зависящую от уровня сложности:
   ```java
   float maxError = (float) ((1.0 - smartChance) * 90.0);
   float yawError = (ThreadLocalRandom.current().nextFloat() * 2f - 1f) * (maxError * 0.5f);
   float pitchError = (ThreadLocalRandom.current().nextFloat() * 2f - 1f) * (maxError * 0.3f);
   ```
   - На уровне 10 погрешность составляет не более $\pm 4.5^\circ$ (мгновенный захват цели).
   - На уровнях 1–2 погрешность достигает $\pm 45^\circ$.
4. Если прямой цели не было, стрелок становится `currentTarget` для ответного огня или преследования, при этом разворот выполняется плавно через алгоритм доводки прицела (без мгновенной 0-тиковой телепортации угла взгляда).


### 2.7. Тактические укрытия, лечение и засады (Cover & Ambush Traps)

1. **Поиск укрытия (Cover Search):**
   - Срабатывает при критическом здоровье ($\le 20\%$ HP или $\le 25\%$ при наличии карты лечения `heal`).
   - Алгоритм через радиальную трассировку лучей `world.rayTraceBlocks` в радиусе 4.0 и 6.5 блоков по 8 направлениям (каждые 45°) ищет безопасную позицию, скрытую от взгляда противника.
2. **Поведение в укрытии:**
   - При наличии карты `heal` бот поднимает щит для восстановления HP.
   - При карте `chameleon` замирает неподвижно для активации невидимости.
3. **Тактическая засада за углом (Ambush Trap & Corridor Holding):**
   - Если бот преследует цель и враг скрылся за углом, бот с вероятностью `smartChance` не бежит слепо вперед, а организует засаду (`isAmbushing`):
     - Занимает укрытие за углом, но не упирается лицом в стену: алгоритм вычисляет открытый угол коридора (`ambushHoldYaw`), направляя прицел в свободное пространство подхода противника.
     - Приседание на Shift отключено как избыточное (ники на сервере скрыты глобально).
     - Предварительно поднимает щит, заряжая бонус карты `Empower`.
     - Непрерывно сканирует сектор и делает моментальный усиленный выстрел из засады при появлении врага в поле зрения.
     - Если за время действия таймера засады (`ambushTicksLeft <= 0`) никто не появился, бот плавно снимает засаду и возобновляет поиск и патрулирование.


### 2.8. Физический движок и навигация по трехмерному рельефу

Физика движения ботов инкапсулирована в [`FakeBot.moveRel(dx, dy, dz)`](src/main/java/com/rounds/bot/FakeBot.java) и методе проверки проходимости [`BotAI.isDirectionClear(loc, heading, dist)`](src/main/java/com/rounds/bot/BotAI.java):

1. **Интеграция движения, гравитация и горизонтальная инерция:**
   - Перемещение осуществляется через нативный NMS метод `sp.move(MoverType.SELF, new Vec3(moveX, finalVelY, moveZ))`.
   - Гравитация рассчитывается как `velY = Math.max(velY - 0.08, -3.92) * 0.98`.
   - **Человеческая горизонтальная инерция (Smooth WASD Momentum):** в `moveRel` скорости перемещения интерполируются с ускорением `accel = onGround ? 0.42 : 0.28`. Устранены резкие 1-тиковые рывки и мгновенные развороты на 180° — бот плавно набирает ход и гасит скорость при остановке и смене направления, симулируя естественную физику игрока.
   - **Плавная доводка прицела (Eased Aim Tracking):** в `aimAt` углы поворота интерполируются через экспоненциальную кривую (`turnFactor = 0.32 + 0.16 * factor`). Прицел плавно замедляется при подходе к цели, исключая неестественные жесткие снапы за 1 тик.

2. **Преодоление препятствий, блочных лестниц, ступеней и защита от стакинга (Auto-Jump & Anti-Stacking):**
   - **Анализ в `isDirectionClear`:** если блок на уровне ног (`feet.isSolid()`) твердый, но блоки на уровне тела (`body.isSolid()`) и головы (`head.isSolid()`) свободны, а пространство сверху открыто — направление **не считается стеной**, а признается проходимой ступенькой.
   - **Защита от стакинга сущностей (Anti-Stacking):** если бот оказывается на голове другого игрока или бота (`dy` от -1.95 до -0.4 и `distXZ < 0.64`), генерируется мгновенный латеральный импульс сброса в сторону (`0.32`), не давая ботам стоять башней друг на друге. Хитбоксы игроков перед ботом помечаются флагом `entityAhead` и не распознаются как твердые ступени, исключая ошибочные запрыгивания на игроков.
   - **Физический прыжок в `moveRel` с сохранением импульса:** бот сканирует пространство в направлении движения на 0.55 блока вперед. Если впереди обнаружена ступенька или коллизия `sp.horizontalCollision` (без других игроков спереди), бот инициирует прыжок с импульсом вперед:
     ```java
     boolean obstacleAhead = ahead.getBlock().getType().isSolid() || sp.horizontalCollision;
     if (obstacleAhead && !entityAhead && !aheadUp.getBlock().getType().isSolid() && !headSpace.getBlock().getType().isSolid()) {
         velY = baseJumpVel; // Ванильная или карточная скорость прыжка
         impulseX += (dx / moveLen) * 0.22; // Импульс вперед без эффекта отдачи назад на лестницах
         impulseZ += (dz / moveLen) * 0.22;
     }
     ```
   - На блочных лестницах вектор движения вперед сохраняется непрерывно, устраняя «отпружинивание» или отталкивание бота назад при запрыгивании.
   - **Защита от зацикливания в углах 2x2:** ведется счетчик безуспешных попыток запрыгивания (`consecutiveJumpAttempts`). При достижении порога или обнаружении непреодолимой двухблочной стены бот прерывает прыжки, совершает разворот и берет обходной курс (`lockedHeadingTicks = 20..35`).

3. **Масштабирование физики прыжков и скорости от карточек и навыка бота:**
   - FakeBot динамически считывает множители `jumpHeightMultiplier` и `speedMultiplier` из `PlayerData`:
     - **Прыжки через 2 и 3 блока:** при карточках высокого прыжка (`jumpHeightMultiplier >= 1.7` или `>= 2.5`) алгоритмы `isDirectionClear` и `moveRel` проверяют свободное пространство на высоте 2.5–3.5 блоков и придают вертикальный импульс `velY = 0.42 * jumpHeightMultiplier`.
     - **Оценка возможностей по уровню интеллекта:** уверенность и безошибочность оценки высоты прыжка зависят от коэффициента `factor`: боты 8–10 уровней точно знают свои габариты и легко прыгают через 2-3 блока; боты низких уровней могут растеряться или не решиться на прыжок.
     - **Скорость передвижения:** скорость стрейфа, погони и патруля масштабируется на `speedMultiplier`.

4. **Плавный спуск по лестницам и склонам (Smooth Stair Descent):**
   - При сходе со ступени лестницы или склона бот не зависает в воздухе и не воспринимает спуск как полет на батуте.
   - Если бот оторвался от земли (`!onGround`), падает (`velY <= 0`) и в пределах 1.1 блока под ним есть твердый пол, ему придается стабильная скорость спуска:
     ```java
     if (!onGround && velY <= 0.0 && padLaunchTicks <= 0) {
         Location checkStepBelow = p.getLocation().clone().subtract(0, 1.1, 0);
         if (checkStepBelow.getBlock().getType().isSolid()) {
             velY = -0.32;
         }
     }
     ```
   - На следующем тике бот чисто приземляется на следующую ступень лестницы без зацикливания.

4. **Проверка габаритов и избегание застреваний в углах:**
   - Метод `isDirectionClear` проверяет лучи ширины плеч (`perpX = Math.cos(rad) * 0.28`, `perpZ = -Math.sin(rad) * 0.28`) на высоте тела, исключая попытки втиснуться в узкие диагональные щели.
   - Проверяется схождение ортогональных блоков в углах (`corner1Solid && corner2Solid`), предотвращая заклинивание на стыках двух смежных стен.
   - **Защита от пинг-понга в коридорах:** если бот 3 раза подряд меняет знак поворота (`consecutiveBounces >= 3`), инициируется поиск выхода `findRoomExit` или разворот на 180° с фиксацией курса на 35 тиков (`lockedHeadingTicks = 35`).
   - **Обход ровных стен без колебаний (Persistent Wall Detour & Dynamic Corner Bypass):**
     - При обнаружении глухой стены алгоритм `findClearDirection` выбирает сторону обхода (знак отклонения -1 для левой стороны, +1 для правой) и сохраняет ее в переменной `wallDetourSign`.
     - При последующих проверках отклонений в `findClearDirection` приоритет всегда отдается сохранению выбранного направления обхода (`offsets` сортируются по `wallDetourSign`), исключая метания из стороны в сторону вдоль одной стены.
     - Фиксация курса обхода установлена на **35 тиков** (~1.75 сек), что дает боту возможность пройти до 5-6 метров и обогнуть препятствие.
     - **Динамический выход из обхода:** на каждом тике проверяется условие `isDirectionClear(myLoc, desiredHeading, 2.0)`. Как только угол стены пройден и прямая видимость цели восстанавливается с запасом в 2.0м, фиксация `lockedHeadingTicks` немедленно обнуляется, `wallDetourSign` сбрасывается в 0, и бот без задержек устремляется к цели.
     - В `ArenaNavMesh.getNearestNode(loc)` добавлена проверка проходимости пути (`isWalkableConnection`) в радиусе 6 метров, гарантирующая, что алгоритм Дейкстры никогда не выберет стартовый навигационный узел с противоположной стороны сплошной стены.

5. **Преодоление ям, прыжки через пропасти 1–3 блока (Gap Jumping) и удержание высоты:**
   - В `FakeBot.moveRel` бот на ходу проверяет пространство прямо перед ногами (`edgeCheck` на 0.6м с падением пола на -0.4м и -1.4м). Если обнаружен обрыв, алгоритм сканирует пространство вперед на 1.4–3.4м в поисках твердой, безопасной платформы приземления (не являющейся батутом или спец-блоком).
   - **Защита от падений с обрывов (Cliff Drop Prevention):** в `BotAI.isDirectionClear` крутые обрывы (перепад пола более 2 блоков) признаются непроходимыми, пока метод `hasParkourTargetAhead` не подтвердит наличие безопасной платформы приземления. Это исключает случайные спрыгивания ботов с верхних ярусов в пустоту.
   - **Фиксация высоты для обзора (High-Ground Vantage Hold):** при подъеме на возвышенность (`deltaY >= 1.5`) бот удерживает позицию на 60 тиков (3 секунды) для сканирования арены и снайперского огня, не спрыгивая сразу вниз.
   - **Трехмерное хэширование ячеек NavMesh (`packCell(x, y, z)`):** для навигационной памяти арены координата высоты $Y$ сжимается в битовый ключ ячейки, гарантируя, что исследование первого этажа не блокирует посещение верхних паркур-платформ.
   - При обнаружении площадки рассчитывается вероятность ошибки прыжка `getJumpErrorChance()`:
     - **Уровни 1–3:** **30%** шанс ошибки
     - **Уровни 4–7:** **20%** шанс ошибки
     - **Уровни 8–9:** **10%** шанс ошибки
     - **Уровень 10:**  **0%** (безошибочный прыжок)
   - **Успешный прыжок:** бот совершает спринт-прыжок (`velY = 0.42`, `impulseX/Z += dir * 0.32`), перелетая расстояние в 1–3 блока и приземляясь на целевую платформу.
   - **Ошибка прыжка (недопрыг):** бот совершает слабый, нескоординированный прыжок (`velY = 0.22`, `impulseX/Z += dir * 0.08`), не долетает до платформы и срывается вниз.

6. **Выход из замкнутых помещений 3x3–4x4 и обнаружение дверных проёмов (Room Escape):**
   - Если бот оказывается в помещении или тупике с 3 стенами (дистанция стен до 4.0м), отслеживается кружение на месте (`spinTicks >= 16`, поворот более 200°): активируется метод `findRoomExit(Location loc)`.
   - `findRoomExit` выполняет радиальное круговое сканирование на 360° с шагом 15° на дальности от 1.0 до 4.5м.
   - В `isDirectionClear` луч головы проверяется строго на высоте **1.7м** (вместо прежних 2.2м), что позволяет безошибочно детектировать стандартные ванильные проемы высотой в 2 блока как открытый проход.
   - Направление с максимальной дальностью свободного пространства признается дверным выходом, ячейка тупика штрафуется в NavMesh (`penalizePath`), а курс фиксируется на 50 тиков (`lockedHeadingTicks = 50`), благодаря чему бот гарантированно покидает комнату без зацикливания.

7. **Навигация по блокам подъема (Up-Blocks / Elevators):**
   - Блоки вертикального подъема (лифты) исключены из списка опасных препятствий (`hazards`).
   - Боты свободно заходят в зону подъема, поднимаются на верхние этажи арены и автоматически определяют безопасную платформу выхода (`findUpBlockExitPlatform`), получая направленный горизонтальный толчок на этаж и спускной импульс приземления (`velY = -0.32`), исключающий зависание в воздухе над шахтой лифта.
   - `ArenaNavMesh` прокладывает вертикальные связи между узлами нижнего и верхнего этажей через координаты блоков подъема.


### 2.9. Умные батуты (Jump Pads) и безопасное приземление (Air Control)

Батуты в Rounds наносят игроку и боту урон в размере 20% от максимального здоровья и запускают сущность высоко вверх. Для ботов реализован строгий протокол безопасного использования:

1. **Временный запрет намеренного выбора в начале раунда:**
   - Намеренный выбор батута алгоритмом поиска (`seekingPadLoc`) заблокирован на случайное время от 3 до 15 секунд (математическое среднее ровно **5.0 секунд**):
     ```java
     this.padCooldown = 60 + (int) (240.0 * Math.pow(ThreadLocalRandom.current().nextDouble(), 5.0));
     ```
   - Это гарантирует, что в начале раунда боты не побегут с обрыва спавна прямо на батуты.

2. **Разрешение ненамеренного срабатывания:**
   - Если бот наступает или падает на батут случайно (во время боя, патруля или от отдачи урона), батут **срабатывает штатно**: наносит процентный урон и выполняет запуск.
   - Никаких искусственных барьеров на спуск с платформ не накладывается.

3. **Естественный импульс взлета и наведение на безопасную часть карты:**
   - При активации батута (`applyJumpPad(launchHeight)`) бот не телепортируется и не получает читерских ускорений. Он динамически вычисляет ближайшую безопасную точку суши арены (`ai.findSafeLandingTarget(p)` через предвычисленный `ArenaNavMesh` или геометрию зоны), ориентирует взгляд в направлении цели и получает реалистичный спринтерский импульс Minecraft (`0.28` блоков/тик):
     ```java
     double normX = dx / dist;
     double normZ = dz / dist;
     this.impulseX = normX * 0.28;
     this.impulseZ = normZ * 0.28;
     float launchYaw = (float) Math.toDegrees(Math.atan2(-normX, normZ));
     setRotation(launchYaw, -10f);
     ```

4. **Естественный контроль полета и безопасное приземление (Platform Landing Air Control):**
   - Находясь в воздухе (`isAirborneFlight`), бот непрерывно подруливает в сторону безопасной платформы с естественной скоростью планирования игрока (`steerSpeed` до 0.24 блоков/тик, соответствующей ванильному бегу в воздухе).
   - **Многоэтапное преодоление дистанции (Double Jump Support):** если безопасная площадка находится дальше дальности одного прыжка (> 8–10 блоков), бот в силу честной физики не долетает до края за один раз и может приземлиться на промежуточный батут/уступ, после чего со второго прыжка гарантированно достигает твердой земли.
   - **Гарантированная непрерывность физики и гравитации:** метод `bot.moveRel(steerX, 0.0, steerZ)` вызывается безусловно на каждом тике полета (даже при `steerX=0, steerZ=0`), гарантируя непрерывное применение гравитации Minecraft и исключая зависание бота в воздухе.
   - **Кеширование и оптимизация:** целевая платформа кешируется на 6 тиков (`landingPlatformCacheTicks = 6`), быстро обновляясь по мере приближения.
   - При приземлении рассчитывается шанс ошибки `getLandingErrorChance()`:
     - **Уровни 1–3:** **10%** шанс ошибки
     - **Уровни 4–7:** **7%** шанс ошибки
     - **Уровни 8–9:** **5%** шанс ошибки
     - **Уровень 10:**  **1%** шанс ошибки
   - **При успешном контроле:** бот с помощью воздушного подруливания планирует и чисто приземляется на обнаруженную безопасную платформу.
   - **При ошибке приземления:** бот испытывает неточное воздушное смещение или дрейф (`driftX/Z`), что может привести к промаху мимо платформы или срыву вниз.
   - Если во время полета в поле зрения находится противник, бот продолжает целиться и вести огонь в воздухе.

5. **Безопасные боевые маневры и обход препятствий (`moveCombatRel`, `executePursuit`):**
   - Во время стрельбы, стрейфа и преследования методы `moveCombatRel` и `executePursuit` проверяют траекторию движения через `isDirectionClear`. Если впереди расположен батут или препятствие, бот обходит его стороной (`findClearDirection`).
   - Для предотвращения «залипания» и дребезга у стен при погоне или отступлении найденный курс обхода фиксируется на 6–8 тиков (`lockedHeadingTicks`), позволяя боту плавно обогнуть угол или стену перед возвратом на прямую линию к цели.

6. **Парирование урона батута щитом (Shield Parry Jump):**
   - У ботов с уровнем сложности 5 и выше (`level >= 5`) с вероятностью **50%** активируется парирование батута щитом:
     - При падении или приближении к батуту бот поднимает щит (`bot.block()`) непосредственно перед ударом.
     - При успешном парировании бот получает полноценный импульс запуска вверх, но урон от батута (20% максимального здоровья) **не наносится** (`damage = 0.0`), сопровождаясь звуком блокирования щитом (`ITEM_SHIELD_BLOCK`).
     - Боты уровней 1–4 не обладают этим навыком и всегда получают полный урон при отскоке.

7. **Преодоление кольца батутов вокруг одиночного центрального блока:**
   - Алгоритм выбора безопасной площадки приземления `findSafeLandingTarget` и `findNearbySolidPlatform` требует ширину платформы `breadth >= 3` (минимум 2-3 соседних блока) и исключает блоки, соприкасающиеся с батутами (`isLocationTouchingJumpBlock`). Одиночный центральный блок никогда не выбирается как точка приземления.
   - Если бот оказывается на одиночном центральном блоке в кольце батутов, вектор наведения батута разворачивается во внешний периметр арены.
   - В `isDirectionClear` при соприкосновении с батутом вызывается `bot.hasParkourTargetAhead`: если через батут на расстоянии паркур-прыжка обнаружена безопасная внешняя площадка арены, бот совершает спринт-прыжок через кольцо батутов на твердый пол.


### 2.10. Синергия способностей карт (Card Synergies & Block Abilities)

Боты анализируют активные модификаторы карт из `PlayerData` и динамически адаптируют тактику:
1. **Пила и ближний бой (`saw > 0`):**
   - При активации щита бот с карточкой пилы переходит в форсированный штурм (`sawRushSpeed = 0.46`), агрессивно сокращая дистанцию до цели (< 2.8 блока), чтобы с максимальной эффективностью распиливать врага огненным кольцом.
2. **Активные способности на блоке щитом:**
   - **`implode > 0`:** активирует блок на средней дистанции (4–7м), чтобы затянуть противника в эпицентр взрыва.
   - **`silence > 0` / `silenceAura > 0`:** активирует блок в радиусе 5м для подавления способностей и блокировки стрельбы противника.
   - **`emp > 0`:** активирует блок при сближении с врагом (< 6м), накладывая сильное замедление.
   - **`overpower > 0`:** наносит сокрушительный процентный урон при блокировании рядом с противником.
   - **`bombOnBlock > 0` / `shieldCharge > 0`:** взрывной спавн бомб и дополнительный запас парирования.
   - **`teleport > 0`:** использует тактический блинк при блоке для уклонения от входящего огня или мгновенного разрыва/сокращения дистанции.
   - **`empower > 0`:** если кулдаун стрельбы $\le 1$ тик и щит не активен, поднимает щит, заряжая бонусный урон перед выстрелом (также используется в засаде).
   - **`heal > 0`:** при ранении (HP < 75%) каждые 20 тиков активирует блок щитом для самоисцеления.
   - **`shockwave > 0`:** в ближнем бою (< 4.5м) отбрасывает врага ударной волной.
   - **`homingOnBlock > 0`:** активирует блок для временного самонаведения пуль на противника.
   - **`tacticalReload > 0`:** использует блок при пустой обойме (`ammo <= 0`) для моментальной перезарядки.
   - *Шанс и тайминг применения способностей:* масштабируются уровнем интеллекта бота (`factor = level / 10.0`).
3. **Модификаторы движения и прыжка:**
   - `jumpHeightMultiplier`: распознает усиленный прыжок и перепрыгивает препятствия в 2–3 блока.
   - `speedMultiplier`: увеличивает скорость стрейфа и преследования пропорционально карточкам скорости.
4. **Тактические стойки:**
   - **`grow > 0`:** переключается на дальний снайперский бой (`CombatTactic.SNIPE`).
   - **`lifestealAura > 0`:** сближение в радиус действия ауры (3.5–4.5м).
   - **`chameleon > 0`:** замирает неподвижно в укрытии для активации полной невидимости.
   - **Тактическая перезарядка:** при `ammo <= 0` уходит в оборону щитом или отступает в укрытие.


### 2.11. Автоматический драфт карт (Card Draft AI)

В фазе драфта карт (`GameState.CARDS`) боты анализируют предложенные карты в GUI:
1. Метод `findBestCardSlot(Inventory inv)` сканирует слоты карт и оценивает их по редкости (`CardRarity`):
   - `LEGENDARY` (вес 5) > `EPIC` (вес 4) > `RARE` (вес 3) > `UNCOMMON` (вес 2) > `COMMON` (вес 1).
2. С вероятностью `factor` (от 10% на ур. 1 до 100% на ур. 10) бот выбирает слот с наивысшей редкостью.
3. В противном случае выбирает случайную валидную карту из предложенных.
4. Бот рассматривает карты в течение случайной естественной задержки от 1 до 10 секунд (в среднем 3–5 секунд), имитируя размышление живого игрока.


### 2.12. Обработка спектраторов при старте раундов, окончании игры и отображение титров

- **При старте игры (`finishStart`)** и **при старте каждого нового раунда (`endRound` / `drawRound`)** спектраторы без команды переносятся в центр зоны новой карты (`currentZoneCenter.clone().add(0, 3.0, 0)`).
- **По окончании фазы выбора карт (`startRound`)** спектраторы **не телепортируются** на центр, чтобы не сбивать выбранный игроком ракурс наблюдения за боем (телепортация применяется только если спектратор случайно оказался в другом мире или дальше 80 блоков от арены).
- **Титры победы и поражения для спектраторов:**
  - Спектраторам без команды (`pTeam == null`) **категорически запрещено** показывать надписи «ПОБЕДА» (`title.won`, `title.game-won`) или «ПОРАЖЕНИЕ» (`title.lost`, `title.game-lost`).
  - Вместо этого спектраторам выводится нейтральный информативный титр в цвете победившей команды: `winner.getColor() + "§l" + "Победили " + teamName.toLowerCase()` (ключ локализации `title.spectator-won`, например, золотисто-желтым цветом `"§e§lПобедили жёлтые"`).
  - При досрочной остановке игры из-за нехватки игроков (`autoStopInsufficientPlayers`) титр победы отсылается только активным игрокам команд.
- **Подсветка игроков в цвет команды для спектраторов (Glowing Outlines):**
  - Для зрителей и выбывших игроков в режиме наблюдателя (`SPECTATOR`) все живые участники боя динамически подсвечиваются контуром свечения (`glowing`) в цвет своей команды (`GameTeam.getColor()`).
  - Для обычных игроков в режиме выживания это командное свечение полностью невидимо, чтобы не нарушать визуальную скрытность (например, карту маскировки `Chameleon`), если только на цель не наложен явный карточный эффект подсветки/обнаружения.


### 2.13. Оптимизация производительности ИИ и матрица характеристик (`CombatProfile`)

Для поддержки одновременной игры 192+ и до 500 автономных ботов без просадок серверного TPS (стабильные 20 TPS даже на серверах с 3 ядрами и 4 ГБ ОЗУ) реализован комплекс оптимизаций:
1. **Предвычисленная матрица профилей (`CombatProfile`):**
   - Все параметры точности, наведения, кулдаунов стрельбы, стрейфа, порогов сближения/отступления, шансов прыжков и ошибок предвычисляются в иммутабельной матрице `CombatProfile[11][4]` при загрузке класса.
   - Вычисления $O(1)$ без выделения объектов и математических формул на тике.
2. **Шахматное чередование поиска целей (Tick Interleaving):**
   - Полное сканирование поля зрения чередуется между ботами по хэшу `(tickCount + entityId) % 2 == 0`, снижая количество RayTrace-запросов к серверу в 2 раза.
3. **Троттлинг 360-градусного сканирования комнат (`findRoomExit`):**
   - Поиск дверных проемов ограничен кулдауном в 30 тиков (`roomExitCooldown`), шаг сканирования увеличен с 15° до 30°, а проверка игроков отключена на этапе геометрического анализа комнат.
4. **Защита от прилипания к стенам при падении (`FakeBot.isOnGround`):**
   - Проверка блока под ногами исключает ложное срабатывание при падении вдоль стен (`velY < -0.1`), опираясь на нативную коллизию NMS `sp.verticalCollisionBelow`.
5. **Предвычисленная навигационная сетка арены (`ArenaNavMesh`):**
   - При старте раунда строится легкий граф вейпоинтов арены `ArenaNavMesh` (120–160 узлов за ~1 мс), разделяемый всеми ботами на сервере.
   - Поддерживает многоуровневые арены, лестницы и вертикальные лифты (Up-Blocks).
   - Предоставляет предвычисленные точки тактических укрытий (`coverNodes`), полностью устраняя необходимость в тяжелых лучевых трассировках при ранении.
   - Обеспечивает быстрый BFS-поиск обходного пути вокруг препятствий при потере прямой видимости (`findNextWaypoint`), плавно направляя бота по свободным коридорам.
   - Патрульные вейпоинты выбираются исключительно из валидных проходимых узлов сетки, исключая выбор точек внутри стен.
6. **Адаптивная 4-уровневая система динамического тикрейта ИИ (AI Level of Detail / LOD):**
   - LOD 1 (0–12м от врагов): 20 TPS (каждый тик).
   - LOD 2 (12–25м от врагов): 10 TPS (каждые 2 тика).
   - LOD 3 (25–40м от врагов): 7 TPS (каждые 3 тика).
   - LOD 4 (>40м от врагов, либо >25м при 50+ активных ботах): 5 TPS (каждые 4 тика).
   - Расчет дистанции исключает союзников: боты, находящиеся рядом с союзниками далеко от врагов, корректно уходят в энергосберегающий режим.
   - Физика движения (`moveRel`) и гравитация сохраняют непрерывность на каждом тике без визуальных задержек на стороне клиента.
   - В цикле расталкивания сущностей (anti-stacking) в `FakeBot.moveRel` добавлено быстрое 1D отсечение по ограничивающему прямоугольнику (`Math.abs(dx) > 1.2 || Math.abs(dz) > 1.2`), исключая тяжелые расчеты расстояний на сотнях сущностей.
7. **Двухэтапная фильтрация целей (FOV и Distance-First в `findVisibleTarget`):**
   - Вместо затратной трассировки лучей через блоки мира (`hasLineOfSight`) для всех сущностей арены цели сначала фильтруются легкими $O(1)$ математическими проверками:
     1) Дистанция меньше расстояния до текущего наилучшего кандидата (`distSq < bestDistSq`).
     2) Попадание в конус зрения 140° через скалярное произведение вектора взгляда и вектора на цель.
   - Тяжелый NMS-метод `hasLineOfSight` вызывается исключительно для кандидатов, прошедших предварительный отбор, отсекая свыше 99% трассировок лучей в массовых боях.
   - Проверка союзников `isTeammate` для ботов выполняется через прямое сравнение назначенной команды `bot.getAssignedTeam()`, минуя обращение к картам игроков и UUID.
8. **Пакетная синхронизация команд и исключение ботов из Scoreboard ($O(1)$):**
   - При старте раунда (`startRound`) и распределении 192+ ботов по командам вызов пересчета скорбордов выполняется пакетом ровно один раз (`applyTeamColor(p, false)` с финальным вызовом `refreshTeamScoreboards()`), предотвращая каскадные вызовы $O(N \cdot T)$ и зависание сервера (watchdog timeout).
   - Боты (`FakeBot`) не имеют клиентского сетевого подключения и исключены из хранения в `playerScoreboards`, исключая бесполезное выделение объектов скорборда в памяти.
   - В `setupTeamsOnScoreboard` поиск команды записи оптимизирован до прямого $O(1)$ (`sb.getEntryTeam(name)` и `sb.getTeam(name)`) без пересоздания и обхода коллекций команд `sb.getTeams()`.


### 2.14. Ограничение распределения ботов по установленным блокам карты

При спавне ботов (`/rbot spawn`, `/rdebug bot spawn`) плагин учитывает физически установленные на арене блоки команд (`joinBlocks`):
1. **Зональный и глобальный поиск доступных команд (`BotManager.getAvailableTeams(Location)`):**
   - Если бот спавнится внутри зоны карты (`MapBlock`), алгоритм ищет блоки команд внутри границ этой зоны.
   - Если в зоне карты блоков команд нет (или спавн происходит в лобби/мире), берутся все установленные блоки команд сервера (`BlockListener.getJoinBlockTeams()`).
   - Если на карте размещены блоки только определенных команд (например, только Красной и Синей шерсти), доступными считаются **исключительно** команды `RED` и `BLUE`.
   - Если ни одного блока команд не установлено (пустой тестовый мир), используется конфигурационный список `config.getEnabledTeams()`.
2. **Балансировка и принудительное переназначение (`BotManager.pickBestTeam(Location)`):**
   - Автоматический выбор команды распределяет ботов поровну только среди команд, имеющих блоки на карте.
   - При попытке вручную указать команду, отсутствующую на карте (например, `/rbot spawn bot1 yellow`, когда стоят только красные и синие блоки), бот автоматически переназначается в доступную команду с наименьшим числом участников, а игроку отправляется предупреждение в чат.
   - Таб-комплит в командах спавна подсказывает только доступные на карте команды.


### 2.15. Преодоление ступеней, паркур, предотвращение залипания в стенах и красный список комнат (Red Zones)

1. **Распознавание ступеней из блоков и паркур (`isBlockStaircase` +30%):**
   - Алгоритм классифицирует 1-блочные подъемы рельефа и блочные лестницы как проходимые ступени при наличии свободного пространства над препятствием, не путая их со стенами и исключая ложные откаты назад при первой попытке подъема.
   - Увеличен импульс толчка вперед (0.24) и добавлена поддержка инерции во время фазы взлета (`jumpAscentTicks`), гарантируя чистое запрыгивание на первую и последующие ступени лестниц и паркур-блоков.
2. **Чёрный список комнат и тупиков (Red Zones):**
   - Замкнутые комнаты (3x3, 4x4, 5x5): при выходе из тупиковой комнаты бот помечает ее как красную зону на **60 секунд** (`RedZone`). Повторный заход во время патрулирования исключается; вход разрешен только при активной погоне за врагом (`currentTarget != null`). При нахождении внутри зоны перемещение наружу в сторону выхода всегда разрешено.
   - Приоритет вертикального выхода: `findRoomExit` перед выбором дверей проверяет наличие блочных лестниц и паркур-подъемов на второй этаж.
   - Одиночные тупики 1x1x1 (`checkSinglePocketEscape`): при обнаружении трех глухих стен вокруг блока бот моментально поворачивает голову и корпус в сторону открытого выхода (без медленного разглядывания угла), фиксирует курс на 35 тиков (1.75 с) и помечает точку как красную зону на **60 секунд**.
3. **Защита от залипания и осмотра стен/углов:**
   - При сближении с препятствием бот мгновенно отворачивается со скоростью до 45°/тик (вместо медленного 12° скольжения взгляда по стене) и временно обнуляет поступательное движение вперед до завершения разворота, предотвращая утыкание в угол соединенных блоков (`isInsideCorner`).


### 2.16. Формат никнеймов, скрытие командных ников и таймаут подсветки

1. **Формат никнеймов и индикация уровней ботов:**
   - Отображение: `<число> HP <Ник>` для игроков и `<число> HP <Ник> [L<уровень>]` для ботов в Tab-листе и над головой.
   - Тег уровня бота расположен строго после его имени и оформлен жирным командным шрифтом (`§l[L1]`).
2. **Командная видимость никнеймов:**
   - Во время боя никнеймы противников скрыты (`Team.OptionStatus.FOR_OWN_TEAM` / `NEVER`); видны только союзники.
   - Наблюдатели видят ники всех игроков.
   - Пинг игроков в TAB окрашивается в цвет их команды (`%rounds_ping%` для форматированного отображения и `%rounds_ping_raw%` для числовых слотов). В `TabCompat` числовое значение `value` передается строго чистым целым числом, а цвет команды устанавливается через `fancyValue`, предотвращая ошибки парсинга чисел в TAB.
3. **Ограничение подсветки и тиканье зелий у FakeBot:**
   - Карта «Марк был хороший» подсвечивает врагов максимум на 10 секунд (200 тиков) после отдаления.
   - У `FakeBot` тикают длительности активных эффектов зелий, обеспечивая естественное затухание подсветки и замедления.


### 2.17. Архитектура карточной прогрессии, выдачи карт и управления характеристиками

1. **Командный протокол характеристик (`/rdebug stats`):**
   - Просмотр: `/rdebug stats show [НИК]` — открыт всем игрокам, если ник не указан — показывает характеристики вызвавшего; отображает боевые характеристики, кулдауны щита и счетчик карт с учетом дубликатов.
   - Модификация: `/rdebug stats add <НИК> <СТАТА> <ЗНАЧЕНИЕ>` — доступна строго администраторам (`rounds.admin`). Устанавливает характеристики в понятных единицах (секунды для `block_cd`, `reload_time`, `atks`, проценты для `atk_speed`, единицы для `ammo`, `dmg`). Команда `setstat` полностью упразднена.
   - Для обычных игроков подсказки таб-комплита ограничены исключительно подкомандой `show`.
2. **Динамическая выдача карт (`/rdebug cards add <НИК> <КАРТА> [РЕДКОСТЬ]`):**
   - Динамическое извлечение редкостей: метод `CardRegistry.getAvailableRarities(card)` запрашивает все вариации семейства карты (`getFamilyId()`), гарантируя поддержку кастомных карт из `cards/custom/` без хардкода.
   - Таб-комплит на 4-м аргументе подсказывает строго те редкости (`COMMON`, `UNCOMMON`, `RARE`, `EPIC`, `LEGENDARY`), которые физически объявлены в файле выбранной карты.
   - Если редкость не указана, `CardRegistry.getRandomFamilyCard(card)` случайно выбирает доступную вариацию.
   - Прогрессия карт: получение карты более высокой редкости автоматически замещает карту того же семейства в инвентаре с пересчетом статов.


### 2.18. Механики легендарных и реактивных карт

1. **«Почки продам, но выстрелю» / Blood Cartridge (ID 123):**
   - Позволяет стрелять во время перезарядки ценой текущего здоровья (Common: 7%, Uncommon: 10%, Rare: 12%, Epic: 15%), предоставляя бонус к урону и криты на старших тирах.
2. **«А нас-то за что?!» / Spite Razorwire (ID 124):**
   - Выпускает веер осколков при попадании по вам (через хук в `RoundsEntities.applyPostHitEffects`). На эпическом уровне осколки самонаводятся и восстанавливают 10% нанесенного урона.
3. **«Бро, я записал откат» / Temporal Recall (ID 125, LEGENDARY):**
   - При активации щита (кд 15с) перемещает игрока на позицию 3 секунды назад, восстанавливает потерянное HP и патроны. Сопровождается шлейфом частиц и полноэкранным заголовком.
4. **«Погоди, шнурок развязался» / Bullet Time (ID 126, LEGENDARY):**
   - Срабатывает 1 раз за раунд при смертельном уроне или HP <= 20%: спасает от гибели, дает 1с полной неуязвимости, на 5с накладывает на врагов Slowness VI + Darkness, замедляет вражеские пули в полете на 85% (с масштабированием шага симуляции без потери истинной скорости), замедляет физику и частоту стрельбы ботов на 85%, а владельцу дает +50% скорости бега.


### 2.19. Стандарты производительности физики пуль, безопасность команд и устойчивость драфта

1. **Протокол физического тика пуль (`RoundsEntities.processCohort`):**
   - Запрещено создавать новые экземпляры `Vector` или `Location` внутри тиковых циклов `bulletPreStep` и `bulletResolve`. Поля `sX, sY, sZ, eX, eY, eZ`, `wallHit` и `rayDir` кэшируются непосредственно в экземпляре `Bullet`.
   - В цикле проверки попаданий по игрокам отсечение дистанции производится строго через скалярное квадратное сравнение `(ddx*ddx + ddy*ddy + ddz*ddz) > maxHitDist * maxHitDist`.
   - Самонаведение (`findNearestEnemy`) не использует пространственный поиск по воксельным чанкам Bukkit, а проверяет только игроков и NMS-ботов мира через `center.getWorld().getPlayers()`.
2. **Протокол безопасного выполнения команд из карт (`Card.java`):**
   - Консольные команды, привязанные к картам, исполняются только после проверки имени игрока на соответствие допустимым символам (исключая внедрение пробелов, кавычек или спецсимволов).
   - Выполнение команд через `dispatchCommand` обязано быть синхронным (`Bukkit.isPrimaryThread()` или `runTask(plugin, ...)`).
3. **Протокол автоматического выбора при истечении таймера драфта (`CardManager`):**
   - Таймер выбора карт в `CardManager.startChoiceTimer` при нулевом остатке времени не выполняет дисконнект игрока, а выбирает случайный индекс из активного списка `pendingCards.get(uuid)`, уведомляет игрока в чат и закрывает меню драфта.

Диспетчеризация выполняется прямым switch в `PlayerData.executeTriggers`.
    - **JSON Schema валидация (`cards.schema.json`):** Единая схема валидации в корне проекта и в ресурсах плагина предоставляет автодополнение параметров карт, описание эффектов и подсветку ошибок в IntelliJ IDEA и VS Code (`# yaml-language-server: $schema=../../cards.schema.json`).
    - **Кроссплатформенная сборка ресурспаков (`CardPackBuilder`):** Таск `./gradlew buildResourcePacks` собирает ресурспаки в директорию `resourcepacks_builds/` на чистой Java (`ZipOutputStream`, `javax.imageio.ImageIO`) без зависимости от PowerShell или Windows GDI+, обеспечивая сборку на Linux, macOS и GitHub Actions.
    - **Быстрая сборка контрибьютора (`quickBuild`):** Таск `./gradlew quickBuild [-PtargetNms=...]` собирает ядро и один целевой NMS-модуль за 2-3 секунды вместо компиляции всех 17 версионных модулей.
    - **Автоматический рендеринг текста на текстурах:** Инструмент `tools/generate_card_textures.py` на базе Pillow считывает имена и описания из YAML всех 118 карт и запекает текст в стандартном разрешении 160x250 (исходное разрешение арта, без последующего ресайзинга) на PNG-текстуры карт в `cards/ru` и `cards/en`: заголовки выравниваются сверху (`y = 2px` для 2 строк, `y = 7px` для 1 строки), описания начинаются с `y = 155px` с 6-точечной тенью без плашки фона (`DRAW_DESC_BOX = false`), оставляя центральный арт полностью видимым. Для каждой вариации карты генерируется отдельная текстура `card<id>-<rarity>.png` с подставленными значениями из списка `values` (плейсхолдеры `{0}`, `{1}`, `{v}`); карты без вариаций рендерятся в `card_<id>.png`.
    - **Непрерывная интеграция (CI):** В `.github/workflows/ci.yml` настроен пайплайн на базе LTS Java 17, включающий выполнение юнит-тестов (`:rounds-api:test`, `:rounds-core:test`), сборку NMS 1.20.4 (`quickBuild -PtargetNms=1204`) и генерацию ресурспаков (`buildResourcePacks`) при каждом Pull Request.
